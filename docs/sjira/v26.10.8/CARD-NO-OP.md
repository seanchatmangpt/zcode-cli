# CARD-NO-OP: zcode-cli serves no A2A/SA2A agent card — consumer-role receipt

**Decision**: NO-OP. zcode-cli does not serve an A2A agent card, and SHOULD
NOT. Generating one would describe an HTTP server that does not exist.

## Evidence (searched 2026-10-08, branch fix/v26926-preview-publish-typed-skip @0bf5391+)

Searched all of `src/` for any servable surface — `createServer`, `.listen(`,
`express`, `fastify`, `http.create`, `Bun.serve`, `Deno.listen`, `serve(` —
zero non-test matches. zcode-cli's real servable surface is:

- **MCP CLIENT**: `src/gall-work.ts` connects out to xaas's execution fabric;
  it accepts connections, it does not accept them.
- **CLI with runtime-capabilities negotiation**: `src/runtime-capabilities.ts`
  (outbound capability negotiation for the CLI process).
- **SA2A runtime consumer**: `.sa2a/manifest.json` declares `role: "runtime"`,
  `depends_on: [ash_a2a, graphlaw, affidavit, xaas]` — this manifest IS
  zcode's discovery surface, on the consumer side of the fleet contract.

## Why no card

A card is honest only if it describes a servable agent surface. zcode serves
no HTTP endpoint, exposes no `agent card` route, and hosts no A2A task
lifecycle. The `.sa2a/manifest.json` is the consumer-side contract and already
carries zcode's identity, role, authority, and dependency closure. A card
would invent a server that does not exist — a fabrication, not documentation.
